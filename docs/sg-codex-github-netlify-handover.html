Singapore Website Handover

How a website change moves from Codex to GitHub to Netlify to the live URL

This is the simple version. The main goal is to understand the journey of one website change from the first edit all the way through to the public site that people can visit.

Step 1

Codex

This is where you make or edit the website content, layout, or code.

Step 2

GitHub

This is where the website files are saved and tracked safely.

Step 3

Netlify

This tool takes the saved files and publishes the new version online.

Step 4

Live URL

This is the website address people open in a browser to see the final result.

What each part does

Think of this like a relay race. Each tool has one job, and the website only goes live when each step passes the work to the next one.

  • Codex helps make the change.
  • GitHub saves the change and keeps a record of it.
  • Netlify notices the new files and rebuilds the site.
  • The live URL is where people see the updated website.

What happens in plain English

  • You change some text, an image, or a page in Codex.
  • You save those website files into GitHub.
  • Netlify sees the update and builds the new version.
  • The public website address shows the updated site.

Codex helps make it. GitHub saves it. Netlify publishes it. The URL shows it.

How to spot where a problem is

  • If the wording or layout is wrong, the issue may be in the edit itself.
  • If the change is not saved properly, the issue may be in GitHub.
  • If the code is saved but the website is not updating, the issue may be in Netlify.
  • If the site is live but the address is wrong, the issue may be with the URL or domain setup.

What he should learn over the next few months

Month 1

Learn what each tool does and follow a small website change through the full workflow.

Month 2

Get comfortable saving work properly in GitHub and checking whether Netlify has updated.

Month 3

Handle a website change from start to finish and know how to tell where a problem sits.
